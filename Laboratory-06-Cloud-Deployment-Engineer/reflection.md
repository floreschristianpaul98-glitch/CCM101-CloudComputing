# Mission Reflection

Writing a `docker-compose.yml` file makes a cloud engineer's job easier because the application configuration is saved in one readable file instead of being entered as many separate commands. The file records which images to use, which ports to expose, and which environment variables each service needs. Once the file is prepared, Docker Compose can create and start the services together. This makes the deployment easier to repeat and helps reduce mistakes when setting up a multi-container application.

YAML indentation is important because it communicates the structure of the configuration. If I accidentally use a tab or put a line at the wrong indentation level, the file may fail to parse or a setting may be assigned to the wrong section. Docker Compose may report an error or fail to configure the services correctly. Checking spaces carefully and reviewing error messages are useful habits when working with configuration files.

Environment variables such as `MYSQL_PASSWORD`, `MYSQL_DATABASE`, and `MYSQL_USER` pass configuration information into the containers. They allow the application and database to use matching settings without rebuilding container images. However, environment variables written directly into a file can expose credentials, so production deployments should use secrets management and avoid publishing real passwords.

Deploying Nextcloud and MariaDB with Docker Compose demonstrates how a private cloud storage service can be assembled from separate components. Nextcloud provides the web interface, while MariaDB is responsible for database information. Using port forwarding to reach the Nextcloud setup page connects the terminal deployment process with the service users see in a browser. Running `docker-compose down` also shows that the stack can be stopped and removed through one command.

Since Mission 1, my understanding of cloud computing has grown from learning general cloud concepts to practicing how services are configured and connected. This activity introduces Infrastructure as Code because the deployment is described in a reusable configuration file. It also helps me become more familiar with the Linux command line, Docker, YAML, and technical documentation. I still need to verify each result in my own playground and capture screenshots as evidence, but this mission gives me a clearer picture of how real applications use multiple services together.
